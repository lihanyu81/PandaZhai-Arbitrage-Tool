# 0.5.31 — 并发预检查与请求耗时拆分

下单前不同平台并行执行权限、账户、仓位和风险检查。同一平台内部保持原顺序与限频。全部结束并通过后重新读取盘口，保留信号、暂停与发送前校验；任何失败或取消均不放行交易。

新增请求诊断：协调器锁等待、限频等待、读取回调及 HTTP 耗时、缓存/合并命中、请求用途。每轮最多 128 条，不保存 URL、密钥、请求/响应体。执行批次保存预检查和最近核验记录，旧记录缺字段保持未知。

HTTP 计时覆盖挂接的 httpx 客户端，不覆盖 SDK 自有客户端、RPC 或 WebSocket；适配器计时不等于交易所撮合耗时。

不更改交易策略、交易条件、限频参数、双腿提交/查单组织方式或一秒重试间隔。保留上一批完成核验后才能提交下一批的限制。
