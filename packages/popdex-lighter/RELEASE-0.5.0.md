# PopDEX-Lighter 0.5.0

本版整合风险退出恢复及 ERROR 持续监控优化，统一定版为 0.5.0。

## 风险退出恢复

- 平仓部分成交、接口暂时失败或旧订单结果不明时，保留退出指令并持续监控；确认原订单终态和最新仓位后，再按实际残仓提交只减仓订单。
- 每轮每边最多一单，补单至少间隔 5 秒，沿用原滑点限制；已经完成平仓的一边不重复下单。
- 退出意图和订单标识在发单前保存，重启后继续核验。已确认退出完成后转为 `STOPPED`。

## ERROR 持续监控

- 普通 `ERROR` 保持风控检查，持续核验原订单、实际仓位及挂单；接口失败不视为零仓位，未知订单不重复提交。
- 已标为 `FAILED` 的执行中，未确认的补偿订单同样需要核验，不能绕过退出保护。
- 原错误原因和“需要人工继续”标记持久保存；重启、自动对账、参数调整及正常结束均不能绕过开仓锁定。
- 原订单全部终态、无挂单、至少两次新鲜仓位与当前 STEP 一致且风控数据正常后，转为 `PAUSED`。人工启动/继续仍需重新核验，不自动恢复套利。
- 仓位不一致时保持监控，不自动猜测或修改 STEP。有持仓但未触发原风控条件时，不仅因 `ERROR` 就强制平仓；已要求退出或触发风控时沿用退出流程。
- 界面分别展示交易状态、风控是否运行、最近核验时间、原错误原因及订单等待原因。

## 升级与数据

已安装节点可直接运行（先暂停运行中的任务）：

```bash
curl -fsSL https://raw.githubusercontent.com/lihanyu81/PandaZhai-Arbitrage-Tool/main/packages/popdex-lighter/update.sh | sudo bash
```

脚本固定下载本版已发布的程序，自动校验 SHA-256、备份及保留原端口。更新失败会尝试恢复旧程序；不会回滚或清空账本。脚本另通过 9 项隔离检查，包含配置保留、ERROR 原订单保留、校验失败与服务启动失败回滚。

保留原账户配置、节点认证、数据目录和 SQLite 账本，不需要清空重装。新增错误标记保存在原任务参数 JSON 中，兼容已有数据；风险退出会话表由程序启动时建立。

升级后打开节点，核对版本 `0.5.0`、订单核验结果、实际仓位和 STEP。风险退出完成前不能恢复开仓；旧订单记录不足以确认结果时仍需人工核实。

## 验证

165 项离线回归测试通过。封包另检查版本、默认模拟配置、原生签名库、界面、归档内容和 SHA-256。启动验证包含预置 ERROR 任务：恢复后风控继续运行、核验通过后保持 PAUSED、人工继续标记仍有效，未自动发单。验证不发送实盘订单。
